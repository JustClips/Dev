# Sweep the Moon for Alien Eggs: architecture

Design and numbers come from `GAME_PLAN.md` (project files, `game-ideas/sweep-the-moon/`). This doc covers how the code is put together.

## Layout

| Repo path | In Studio | What lives there |
|---|---|---|
| `src/shared/` | `ReplicatedStorage.Shared` | Configs (incl. `World` map layout and generated `Assets` ids), `AssetLibrary`, `BigNum`, `Format`, `Net`, `Grid`, `Types`, `Signal`, `AlienModel` (placeholder fallback) |
| `src/server/` | `ServerScriptService.Server` | `Main` (boot), `Services/*`, `Lib/*` (ProfileStore, mock DataStore, touch helper, `MapBuilder` terrain + props) |
| `src/client/` | `StarterPlayerScripts.Client` | `Main` (boot), `State`, `Ui`, `Controllers/*` |
| `src/gui/` | `StarterGui` | Stud-style screens generated by `tools/gen_ui.py` (see `docs/UI_STYLE.md`) |
| `src/workspace/Moon/` | `Workspace.Moon` | Gameplay parts only (base pads/spawns/parks, sell pad, gates, walls), generated by `tools/gen_world.py` |
| `art/` | | Blender scripts for every model, icon and animation (`art/README.md`) |
| `tools/` | | `upload_assets.py` (Open Cloud upload), `gen_world.py`, `gen_ui.py` |
| `default.project.json` | | Also sets `Workspace.StreamingEnabled` and the Moon lighting + sky |

Leaf tiles are not in the repo and not parts. `DustService` keeps only data (HP, cleared, golden) for about 8,800 tiles generated from the zone bounds in `Config/Zones.luau`; clients draw them (LeafController). Each tile is a clump of leaves (`Zone.Ground` images from `art/vfx/ground.py`), and `Grid.trashKind(id)` makes a few percent of tiles a piece of trash (can, bottle, pizza box...) that pays `Economy.TrashMult` times more. `Grid.hash(id, salt)` gives every client the same random look per tile.

## Boot

`Main.server.luau` creates every remote (`Net.setup()`), requires the services in a fixed order, calls every `Init(services)`, then every `Start()`. Services reach each other through the `services` table, so there are no require cycles. The client `Main.client.luau` does the same for controllers.

Players only get a character once their profile has loaded (`CharacterAutoLoads = false`), so nobody plays on unsaved default data. If the load fails, the player is kicked with a friendly message.

## Server services

| Service | Job |
|---|---|
| DataService | Session-locked profiles (`Lib/ProfileStore`): lock by token in `UpdateAsync`, steal after 30 min stale, autosave every 60 s, release on leave, `BindToClose` flush. Uses an in-memory mock in Studio when the place is unpublished or API access is off. Holds each player's `Session` (`Data` = saved, `Runtime` = this session only). |
| StateService | Sends each player one `PlayerState` snapshot (at most every 0.2 s) and owns `ReplicatedStorage.ServerState` attributes (Moon %, event, luck). Also works out the tutorial step. |
| AnalyticsService | Onboarding funnel (spawn → first sweep → sell → egg → hatch → tool → zone → rebirth), economy sources/sinks, custom offer events. |
| AssetService | Loads every Blender model with `InsertService:LoadAsset` at start, cleans and rigs it (`AssetLibrary.prepare`), and stores it in `ReplicatedStorage.Assets` (attribute `Ready`). Failed models fall back to part-built placeholders. |
| WorldService | Finds `Workspace.Moon`, sets up lighting and the star sky, builds the terrain and structures (launch pad, Garage, Upgrade Station, base floors, signs) at start, then places all props once assets are ready (`Lib/MapBuilder`). Sets `Workspace` attributes `TerrainReady` and `PropsReady` for the loading screen. Owner name and avatar on each base sign. |
| BaseService | Gives each player a base, spawns and respawns them there. Avatars spawn no bigger than the default size (`Lib/Avatar`: scales clamped to 100%, classic proportions) and players and cars don't collide with each other (collision groups `Players` / `Vehicles`). Getting into a car puts the hand tool away, and it can't be re-equipped while driving. |
| BoostService | Server luck tiers (time stacks per tier, highest active wins), personal boosts (2x cash, Luck and Speed potions), and the single cash multiplier formula. |
| DustService | Tile data only: HP, clearing, regrowth per zone, golden piles, the World Cleaned counter. 0.1 s batches of tile ids go out as `TilesCleared` / `TilesRestored` / `TilesGolden`; `GetDust` returns the cleared and golden ids for a joining client. |
| SweepService | Validates `SweepTick(position)`: rate (10/s token bucket), distance from the character, zone unlocked. Applies tool power through the grid lookup, fills the backpack, rolls eggs. Keeps the sweep combo (x1 to x3, `Economy.Combo`), pays 15x on golden piles (`DustService` gilds a few tiles per zone, `Economy.Golden`) and pops dust bunnies in the sweep circle. |
| DustBunnyService | Part-built dust bunnies (3 per zone) that hop around and flee players. Sweeping one pays cash (seconds of your earnings), sometimes a potion or an egg; it comes back after 12 s. `Economy.Bunnies`. |
| ToolService | Tool ladder (tiers 1-6), tool in hand, and cars (`Tools.Vehicles`): buying with cash, Robux unlocks and rentals, spawning at your feet (hotbar slot 2) or on the Garage pad. Cab vehicles seat the driver `SeatDrop` studs lower so the head fits under the cab roof. |
| UpgradeService | The upgrade tree from `Config/Upgrades.luau` (Slime RNG style): full-screen honeycomb of 49 hexagons bought with cash (tap to buy). Buying a node opens its neighbours; outer nodes need rebirths. Lab hexes (Egg Lab, Lucky Lab, Pet Lab) open their own sub-trees. Each node raises one stat (power, backpack, speed, luck, leaf value, sweep size, all cash, pet income, offline cash, combo max/time, Lucky Sweep chance/payout, golden piles, bunny rewards, hatch speed, eggs at once); services read them with `Upgrades.stat` / `Upgrades.multiplier`. `BuyUpgrade(id, count)` also does Buy Max. Reset on rebirth. |
| TraderService | The Pet Trader: an NPC (R15 from a HumanoidDescription, block figure fallback) behind a market stall on every base (`World.traderCFrame`, stall in MapBuilder) with a "Talk" prompt (attribute `Opens = "Trader"`). `IsNear` (18 studs) gates the Inventory remote's SellHeld, SellAllPets and Appraise. |
| BackpackService | Leaf units + their cash value, `GiveCash` / `TrySpend` helpers, and selling. Leaf dumps (`World.Dumps`, two bins beside the market hall): standing or driving on a dump's circle pours the bag in bit by bit (a full bag takes `Economy.DumpSeconds`), paying as it goes, with player attribute `Dumping` and `DumpTick` for the effects. Sell Anywhere pass: `SellNow` sells the whole bag, and Auto Sell (`Settings.AutoSell`, toggled with `SetAutoSell`) sells when the bag is full. Every character wears the voxel `Backpack` model ("LeafBag", welded to the torso; its Fill part has a Weld so clients can grow it) and player attribute `BagFill` (0..1, 5% steps) says how full it is. |
| ZoneService | Gate labels and ProximityPrompts, paid unlocks, HUD teleports (`Teleport`: Base / Rocket / zone; a locked zone sends you to its gate; no teleport while carrying an egg). |
| EggService | Egg chance per tile, guaranteed first egg (tile 12), physical eggs picked up with a hold prompt (`PickUp`, 0.35 s, 10 studs; owner-only for 15 s, each remembers the zone it was found in), carrying, delivering (a distance check: walk into your base's hatchery). Delivered eggs go to the inventory, nothing hatches on its own. |
| InventoryService | The inventory: eggs (`data.Eggs`), pets (`data.Pets`, `Placed = true` when on the base) and items (potions). One remote, `Inventory(action, arg, position?)`, for every inventory button and base prompt: HoldEgg, StopHolding, PlaceEggAt (a spot the player clicked in their pet park), PlaceEgg (auto spot), PlaceBestEggs, OpenEgg, OpenReady, SkipHatch, PlacePet, PickUpPet, EquipBest, SellPet, UseItem. Bag limits in `Economy` (PetBagSize, EggBagSize). |
| HatchService | Eggs grow in the pet park. The egg limit is the incubator count (4, +1 per 2 rebirths, max 8). The player holds an egg out (a welded `HeldEgg` model) and clicks a spot; `Shared/EggSpots` checks the spot (inside the park, clear of props, spaced from other eggs) on both client and server, and saves `X`/`Z` in base space. The player places eggs; timers are saved as unix `EndsAt` (they keep running offline). When ready the player opens the egg: the pet is rolled from the egg's zone pool (`Aliens.pool`), with mutation and Huge rolls scaled by server and personal luck. Skip Hatch finishes the egg the player picked. Weights (`Config/Weights`): every egg rolls a size class (Normal, Big, Heavy, Giant, Colossal; luck makes the big ones likelier) and a kg weight; the pet's weight is the egg's size multiplier x 0.85-1.15, and its income scales with weight (`Aliens.income`). |
| AlienService | Base pet limit (slot count), income every second from placed pets, offline income on join, publishes `base.Aliens` (one Folder per placed pet, named by uid, rendered by every client's PetController) and `base.Hatching` (growing eggs right on the grass at their saved spots, scaled by weight), the top-3 followers attribute. |
| RebirthService | Cost, reset, +50% cash per rebirth. |
| EventService | Egg Rain state machine (eggs fall from the sky via `EggDrop`). |
| WeatherService | Day/night cycle + weather/moon rolls, Grow a Garden 2 style (Config/Weather). Upgrades growing eggs with weather mutations, lightning/star strikes, faster egg growth, leaf regrow, Mega Moon egg drops; bonuses for other services; admin chat `/weather <id>`, `/night`, `/day`, `/eggrain`. Client: WeatherController. |
| ShopService | Idempotent `ProcessReceipt`, gamepass checks, gifting, what each product grants. `CashFor(player, seconds, floor)` scales free cash rewards like cash packs. |
| RewardService | Free rewards from `Config/Rewards.luau`, one remote `Rewards(action, arg)`: ClaimDaily (7-day streak in `data.Daily`, a missed day restarts it), ClaimPlaytime(i) (session playtime counted by its 1 s loop), StartStay (the stay offer: a potion after 5 more minutes, 30 min cooldown), ClaimGroup (off while `Rewards.Group.Id` is 0), SignUp(eventId) (`Flags.EventSignups`: 1 signed up, 2 rewarded; the gift is paid when a signed-up player is in game during the event). Writes the event name and countdown on the plaza event board. A live event also multiplies server luck (`BoostService:GetServerLuck`). |
| OfferService | Contextual offers with cooldowns, never before the first hatch. |
| LeaderboardService | leaderstats and the overhead tag. |

## Remotes (`src/shared/Net.luau`)

Client → server (all rate limited): `SweepTick`, `OfferResponse`, `SetAutoSweep`, and the functions `GetState`, `BuyNextTool`, `Rebirth`, `PromptPurchase(key, giftToUserId?)`, `ToggleVehicle`, `SpawnVehicle(id)`, `BuyVehicle(id)`, `BuyUpgrade(id, count?)`, `EquipTool`, `Teleport(target)`, `Inventory(action, arg)`, `Rewards(action, arg)`.

Server → client: `PlayerState`, `TilesCleared` (buffer of u16 ids), `SweepResult`, `Notify`, `Announce`, `HatchCompleted`, `WelcomeBack`, `ShowOffer`, `EggDrop`, `WeatherStrike`, `EggUpgraded`, `BunnyPop`.

The client never sends amounts. Every cash, egg and tool change happens on the server.

## Saved data (v3)

See `Types.ProfileData` and the template in `DataService`. Pets, eggs and incubating eggs carry string uids (`DataService:NewUid`). The state snapshot only carries the full Pets/Eggs/Items tables when `Runtime.InvVersion` changed (`InventoryService:Touch`); the client keeps its last copy. Cash and TotalDust are `BigNum` tables (`{m, e}`), safe to store as-is. `ReceiptsGranted` maps purchase id → recipient user id, trimmed to the newest 100. To change the schema, bump `CURRENT_VERSION` and add a step to `MIGRATIONS`.

## How to add things

- **A tool:** add a row to `Config/Tools.luau` (keep tiers in order). For a Robux skip, add a `ToolSkipN` product in `Config/Products.luau`.
- **An alien:** add a row to `Config/Aliens.luau`. It joins its rarity's Landing hatch pool and the index automatically. Zone variants (Crystal, Shadow, Magma, Frost) are generated from `ZONE_SETS` and only hatch from eggs found in their zone.
- **A reward or event:** edit `Config/Rewards.luau`. Daily cards, playtime gifts and the stay reward are lists of `{Kind = "Cash" | "Item" | "Egg", ...}`. For an event add a row to `Events` with unix `StartsAt`/`EndsAt` (UTC); the plaza board, the Rewards window and the luck boost pick it up. To turn on the group reward, set `Group.Id` (and `Group.Name`).
- **An item:** add a row to `Config/Items.luau` and handle its effect in `InventoryService:UseItem`.
- **A zone:** add a row to `Config/Zones.luau` with bounds that don't overlap others (keep total tiles under ~8k), add ground for it in `src/workspace/Moon/Ground.model.json`, and if it has a price add a part named `Gate_<ZoneId>` in `Gates.model.json` (ZoneService labels it and adds the prompt).
- **A product:** add it to `Config/Products.luau` with `Id = 0` and an existing `Kind`, then run `python3 tools/create_products.py` (creates it on Roblox through Open Cloud and writes the ID back). For a new kind, add it to `Types.ProductKind` plus a function in `GRANTS` in `ShopService`. Put it in a shop tab in `ShopController`.
- **New UI art:** edit the `.model.json` files in `src/gui`. Controllers only look up elements by name, so keep the names.

## Extension points (not built yet)

Egg stealing, trading, codes. Base plots, eggs and hatching are already separate services, so stealing can hook into `EggService` and `HatchService` without touching the rest.
